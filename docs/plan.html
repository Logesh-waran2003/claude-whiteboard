Agent-native canvas

Plan, spec and milestones. Written 2026-11-12. Product name: Agent Board. Research checked live on 2026-11-12.

Recommendation: build our own canvas in which agents describe a graph (nodes, edges, groups) and a layout engine places it. The canvas enforces the quality rules (no overlaps, no squeezed labels) after every change. Save boards as JSON Canvas files in the repo, so Obsidian opens them and git can diff them.

Effort: 15 working days in 4 parallel tracks, ~45–60 agent-hours. Target finish: Thu 2026-12-03. Your reviews: ~30 min per milestone.

2. Why agents draw badly, and our answer

Cause (seen in our own boards)Our design answer
The agent guesses pixel coordinates, so shapes collide and arrows are long and diagonalGraph in, layout out. The agent sends nodes, edges and groups. dagre or the grid packer places them. Coordinates are optional
The agent cannot see the render, so labels overlap and wrapMeasured feedback. Each change returns a quality report (overlaps, wraps, crossings). A PNG snapshot is available for vision
A batch half-applies, then failsTransactions. Validate the whole batch, then apply it atomically. Errors name the exact op and field
The user edits while the agent worksVersions and diffs. Each read returns a version number. A write against an old version gets the diff, not a silent overwrite
A re-layout loses the meaningSemantic fields (role, layer, lane, pinned) live on each shape, so a re-layout keeps the structure

3. Spec

3.1 File format

A .canvas file following JSON Canvas 1.0, with x- extension fields. Unknown fields are kept on save.

{
  "nodes": [
    { "id": "api", "type": "text", "text": "Bun server",
      "x": 0, "y": 0, "width": 240, "height": 120,
      "x-shape": "rect", "x-by": "agent:claude",
      "x-role": "service", "x-pin": false },
    { "id": "srv", "type": "group", "label": "Local server",
      "x-layout": "dag-lr" },
    { "id": "f1", "type": "file", "file": "server/index.ts" }
  ],
  "edges": [
    { "id": "e1", "fromNode": "ui", "toNode": "api",
      "toEnd": "arrow", "label": "chat",
      "x-route": "elbow" }
  ]
}

3.2 Layout and invariants

  • Group layouts: dag-lr, dag-tb (dagre), grid (stickies), free.
  • Groups are laid out recursively, inside first.
  • After every apply, these must hold: 0 text overlaps, 0 squeezed labels, children inside their group, a gap of 24 px or more, and edges that do not pass through nodes (elbow routing).
  • The engine never moves pinned shapes or user shapes.

3.3 Agent API (MCP and in-process)

read_boardCompact text outline, version, and the diff since the agent last read
snapshotPNG of the board or of chosen ids, for vision
applyAtomic batch: add_node, add_edge, update, remove, group, set_layout. Returns ids and a quality report
layoutLay out a group or the whole board again
checkQuality report only
findFind shapes by text, file or role
focusMove the user's camera
 
apply({ version: 41, ops: [
  { op: "add_node", ref: "ui", text: "Browser", shape: "rect", parent: "app" },
  { op: "add_edge", from: "ui", to: "api", label: "chat" },
  { op: "set_layout", group: "app", layout: "dag-lr" }
]})
→ { version: 42, ids: { ui: "n_7f" },
    quality: { overlaps: 0, wraps: 0, crossings: 1 } }

3.4 Canvas for people

  • React + SVG. Clean mode and hand-drawn mode (rough.js).
  • Select, marquee select, move, resize, text editing, copy and paste, shortcuts.
  • Undo history uses the same ops as the agent: one log, one undo stack.
  • Performance goal: 60 fps with 1,000 shapes, using viewport culling.
  • Not in v0: live multiplayer, images, mobile touch polish, plugins.

3.5 Quality score: how we prove "better"

We use 20 benchmark prompts (architecture, flow, sticky clustering, 2×2 map, sequence). A scorer measures overlaps, squeezed labels, edge crossings, edges through nodes, alignment and area. It runs in CI. Day-6 baseline: the current tldraw app. Launch bar: 0 overlaps and 0 squeezed labels on 20 of 20 prompts, and fewer crossings than the baseline.

What we learn

  1. Everyone ships 3 layers: an MCP server (the tools), a skill (how to use the tools well), and a plugin that bundles both. Figma's skill says "load before every call". The skill carries the quality.
  2. Agents send text formats, not pixels: Mermaid (Figma, Excalidraw+), semantic JSON (Excalidraw+), SVG DSL (Miro), DSL (Eraser). This matches our "graph in, layout out" design.
  3. Self-check is now expected. Excalidraw+ already reports overlaps and arrows through shapes on each write. Our quality report alone is not unique. We need it anyway, and we must go further: a public benchmark and a CI check.
  4. All of them are cloud and need an account, except tldraw offline. tldraw offline is local and BYO agent, but uses a custom licence and saves .tldraw files.
  5. No one makes the repo the source of truth. No one checks a diagram against the code in CI (Eraser has Git sync, but cloud only).
